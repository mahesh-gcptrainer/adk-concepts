02 · Architecture

Your process vs. Google's sandbox

ADK code runs and calls out; the Managed Agents API runs inside Google's Antigravity harness — reasoning, tools, and file I/O all happen inside an isolated sandbox that, by default, has no network access or credentials.

03 · In one analogy

Your car, or a taxi

Same three modes, told as a trip. Toggle above still drives this.

Where this analogy stretches thin: "zero maintenance" oversells the taxi side — with the Managed Agents API you still configure the agent, decide what it can reach on the network, and are expected to review its actions. It's closer to a taxi where you still hand the driver the route and a toll pass. And it's a Pre‑GA service, not a licensed cab company with an established track record yet.

06 · Read this before you commit

    
What the Managed Agents API won't do (yet)

    
Straight from Google's docs — not edge cases, but hard limits worth knowing before you build a course demo or a pilot around them.

    

      ⚠ pre-GA limitations
      

        
No client or MCP tools inside ManagedAgent
Only server-side tools run in the managed sandbox; passing a function tool or MCP tool raises NotImplementedError.

        
Streaming only
ManagedAgent uses streaming interactions; background polling isn't fully supported yet.

        
Pinned to global
The Agent Platform backend serves the Managed Agents API only from the global location — regional endpoints error out.

        
No network or credentials by default
Every agent starts with zero outbound access; you opt in explicitly, scoped as narrowly as possible.

        
Not for sensitive data yet
Google's own terms: this is Pre-GA — don't point it at proprietary or confidential data, and don't rely on it in production.

        
ADK never touches the control plane
ManagedAgent only calls the Interactions API — it can't create or configure a new managed agent resource.
